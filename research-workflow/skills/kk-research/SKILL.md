# 独立研究模式

围绕用户问题建立独立研究上下文，通过原文取证、输入披露和实际请求审计控制分析过程。

## 使用时机

仅在用户明确要求开启独立研究时使用。日常聊天保持默认行为。

公开入口名称为 kk-research。仅有本文件不能注册命令或建立隔离会话；部署者需要将 /kk-research 与实际执行器路由绑定。若无法核实插件接管和隔离能力，明确说明“独立研究通道尚未接管”，停止代替独立核心模型分析。

## 使用准备

确认本地取证客户端、clean-research 插件、独立模型服务和持久会话存储已配置。需要外部补证时，另行配置网页工具或金融数据供应商。密钥只从使用者的安全配置读取。

部署者应实现并逐项验收：开启、追问、新建研究、状态查询、关闭外部取证、退出、恢复和暂停维护。公开命名需要同步到插件解析、状态处理和测试中，文件改名不能单独证明入口可用。

## 角色分工

- Agent 1：接收并转交原始问题，默认保留用户原话，不形成研究观点。
- Agent 2：查询本地资料，并按需要补读原文。
- Agent 3：根据核心模型指出的缺口，从准入来源取得外部资料。
- Agent 4：判断证据是否充分，提出补证要求，分析并与用户讨论。

这些角色可以由程序与独立模型调用共同实现。角色名称只用于说明职责。

## 核心模型的输入范围

对可控请求内容使用白名单：

1. 用户原始问题和明确要求。
2. 最小必要研究规则。
3. 可追溯原文、原始数据、必要来源及限制。
4. 本项研究中用户与 Agent 4 的讨论。

将主会话的无关历史、操作日志、重试过程、认证信息、工具定义和其他角色的预设结论留在执行侧。保留反向证据、样本分母和方法限定，避免筛选材料时先行决定结论。

## 研究流程

1. 记录本轮原始问题、研究标识和外部取证权限。保密资料需确认允许发送的范围。
2. 先执行本地检索，按需要补读原文；保留查询、文档标识、来源和字符范围。
3. 发送前展示本轮实际检索记录与材料清单，再调用核心模型。
4. 核心模型判断是否需要补证。资料充分时停止取证；有缺口时提出具体主体、时期、口径和材料要求。
5. 执行器先检查权限、来源准入与隐私，再调用外部通道。关闭外部取证时同时阻止网页与金融调用。
6. 取得新材料后，先披露增量清单，再调用同一研究上下文中的核心模型。设置有界补证预算，仍有缺口时清楚说明。
7. 退出、恢复和新建研究分别管理状态。维护要求交给宿主处理，维护问答留在研究历史之外。

## 输入披露

逐条展示实际进入本轮请求的标题、来源、日期、全文或片段、传入范围和限制。分别记录检索命中、取得正文、装入请求和独立核验。

材料清单从实际发送载荷生成，并通过研究标识、轮次、尝试次数与请求指纹关联。展示异常时停止本轮发送。长清单与操作日志保存在执行侧；核心模型只接收必要证据及简短状态。

## 来源与隐私

本地解析和检索在电脑上完成，选中的原文会交给分析模型服务商。外部查询仅发送与缺口相关的公开主体、事项、时期和口径，避免携带私有正文与认证。

优先使用公司原始披露、监管及统计发布、产品官方文档、论文原文，以及方法明确的数据原始发布。对网页检查精确域名、路径、重定向和实际正文。

券商研报作为机构观点材料，保留机构、作者、日期和阅读范围。预测与判断归属原作者；关键事实按需要另核原始发布。结构化数据保留供应商、主体、时点、报告期、单位及指标口径。

## 失败与验收

取证失败只交接简短缺口，后台保留真实错误。独立推理失败时停止本轮，保持上下文边界。

验收需读取实际发送请求和回执，核对进入、追问补证、关闭外部取证、退出、恢复及新建研究。界面标签和技能加载只证明相应展示或加载阶段；完整隔离还需通过执行入口与发送内容核验。

本包未提供插件和客户端代码，也未在新环境运行验证。附件、忙时输入、后台排队及具体金融接口应按部署版本分别验收。
