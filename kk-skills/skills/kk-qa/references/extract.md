# 问答提取流程

把材料整理成有依据、有承接的问答链，默认直接在对话框输出。

## 第一步：获取内容

按输入类型使用现有工具。

| 输入 | 工具 | 要点 |
|------|------|------|
| 普通网页 | `web_extract` | 读取正文；抓取失败时按 `blocked-page-recovery` 技能处理 |
| arXiv 链接 | `web_extract` | 优先读取 HTML 正文或 PDF，覆盖方法、实验及局限 |
| PDF、本地文件 | `read_file` | 长文件根据返回的行号继续读取；扫描件按 `pdf` 技能处理 |
| 用户直接提供的文本 | 直接阅读 | 使用当前对话中的完整材料 |
| 论文名、书名 | `web_search`，再用 `web_extract` | 核实标题、作者及可取得的正文范围 |

至少取得核心论点、论证链、关键例子和边界讨论。只有摘要或节选时，明确说明覆盖范围；无法读取的内容不作推断。

## 第二步：找出论证结构

先梳理以下内容：

- **核心论点**：用一句话说明作者主张什么。
- **关键转折与分支**：逐项找出影响结论的推理转折和重要分支，分别说明作者怎样从证据或前提走到下一个判断。按材料实际内容梳理，不预设数量。

如果某个转折缺少根据，回到相应段落核对。不要按固定时长等待，也无需把内部草稿另存为文件。

## 第三步：设计问题链

围绕关键转折设计问题，每个问题应满足：

1. 需要解释方法、原因、代价或条件，单句定义不足以回答。
2. 答案可以在原材料中找到根据。
3. 与前面的问题存在明确联系，例如追问上一结论的实现方式或适用范围。

设计规则见 `references/question-design.md`。优先混合动作、因果和边界三类；用户明确要求比较时，可以加入比较型问题。

按论证依赖关系排序：先交代核心问题，再说明解决办法，随后讨论依据、代价和限制。题数随材料确定，按 `references/question-design.md` 的「数量与覆盖」检查是否需要拆分或合并。内容较多时按主题分组，逐组核对覆盖，并保持在对话中交付。

## 第四步：写答案

问题标题之后，先用一句话说明它与前文的联系或当前切入点，然后按以下三段展开。

```markdown
**结论**：一句话直接回答问题，脱离上下文也能读懂。

**形式化**：用文字和简单符号表示一行关系。

**怎么想到的**：
- 第一步，说明原文给出的前提或证据。
- 基于这个前提，说明下一步判断。
- 因此，解释作者如何得到结论。
```

具体要求：

- **结论**：写明对象和判断，避免只说「这很重要」或「效果更好」。
- **形式化**：用中文、英文及简单符号表达关系，一行内放完。需要计算的数值必须使用工具核对。
- **论证步骤**：通常 2-4 条，每条推进一步。原文证据和补充推断要分清；涉及适用条件或证据缺口时，在相应步骤中说明。

形式化可采用以下写法：

- 角色关系：`协调者 = 拆分任务 + 汇总结果`。
- 流向关系：`原文证据 → 中间判断 → 结论`。
- 递进关系：`发现错误 → 修正假设 → 再次验证`。
- 用户要求比较时：`方案 A：并行探索；方案 B：逐步验证`。

## 第五步：检查问题的承接

通读整串问题，检查后一个问题是否由前面的结论、前提或边界引出。

如果某个问题与其余部分没有联系，判断它是否值得保留。需要保留时补充连接句，并调整顺序；内容重复时合并。论证允许分支，不强迫每个问题都依赖紧邻的上一问。

## 第六步：检查内容质量

- [ ] 问题涉及方法、原因、代价或条件。
- [ ] 每个答案的结论、形式化、怎么想到的三段齐全。
- [ ] 形式化一行能读懂，关系与原文一致。
- [ ] 问题之间的联系写清楚。
- [ ] 问题尽量控制在 20 字以内。
- [ ] 术语已用具体动作、对象或场景解释。
- [ ] 核心论点、关键转折和重要分支均有对应问答；适用条件已交代，重复问题已合并，每问的论证任务清楚。
- [ ] 每个论据有材料支持，补充推断已标明。
- [ ] 论证涉及的适用条件和证据缺口已说明。

未通过的项目先修改，再交付。

## 第七步：在对话框交付

使用 Markdown，直接展示完整正文。默认不生成文档、文件名、时间戳、YAML 元数据或下载附件，也不追加保存提醒。

推荐结构：

```markdown
# {概括核心观点的标题}

来源：{原文标题及可核验的链接，或用户提供的材料名称}

## 引子

用 3-5 句话说明作者讨论的问题、核心主张及阅读这串问答的切入点。

## Q1：{简短的问题}

用一句话交代本问的切入点。

**结论**：……

**形式化**：……

**怎么想到的**：
- ……
- ……

## Q2：{承接前文的问题}

用一句话说明为什么接着问这一点。

按相同的三段结构回答。

## 收口

用一句话点明作者的核心贡献。
```

格式要求：加粗用 `**文字**`，列表用 `-`，标题用 `#` 或 `##`。段落之间留空行。中文语句使用全角标点，代码和关系式使用反引号。

## 用户要求保存时

只有用户明确要求保存、导出或生成文件时，才调用写入工具。保存已确认的问答内容；用户指定位置时按指定位置写入，否则放入该任务所属项目目录。需要日期命名时，通过工具取得实际日期。写入后报告真实路径。

## 验收

读者能够顺着问答理解作者如何得到结论，也能看清论据的范围。全文默认在当前对话中可直接阅读；文档写入必须有用户明确要求。
