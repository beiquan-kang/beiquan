# 逐字稿成品规范

## 处理口径

- 会议纪要所附逐字稿默认采用轻度整理，按下文「轻度整理尺度」处理。目标是保留全部实质信息、发言顺序和说话口吻，清理阅读中的无实质口语堆叠。
- 单独要求逐字稿时默认严格保留口头语、重复、结巴、自我修正和未完句，只校正有依据的识别错误及标点、分段。
- 用户明确要求轻度整理、原样保留或其他尺度时，以当次要求为准。已有逐字稿须核对符合本次口径后复用，用户提供的原文件保持不变。

## 成品内容

使用 YAML frontmatter，字段限定为 `title` 和 `source`。标题与来源沿用用户提供的精确值；来源按用户指定的 `@url:` 加反引号形式保存，例如：

```markdown
---
title: "原始标题"
source: "@url:`https://example.com/media`"
---

说话人A：本轮发言的第一段。

本轮发言的后续段落。

说话人B：另一位说话人的完整发言。

说话人A：再次接话时的完整发言。
```

删除正文所有时间戳及额外标题。说话人身份未核实时用稳定的 A、B 标签。每次连续发言只在开头标明一次说话人，内部可自然分段；换人后才再次标明，原说话人重新接话时再标一次。单人独白全文只标一次。引用他人的话仍属于当前说话者。

## 忠实校对

1．修改既有文件前，在项目的临时任务目录备份原稿；校对期间保持原音轨与识别 JSON 不变。成品验收后删除本次备份、识别 JSON 及其他过程文件，保留用户提供的原始资料。
2．结合全文上下文校订，完整保留各方发言的实质内容及其原有顺序；说话人切换、有实质意义的自我纠正和跨段衔接均须保留。
3．按本次口径处理口头语、重复、结巴和未完句。严格保留时沿用原表达；轻度整理时仅作下文允许的局部删改。发言中的事实、推理、例子、条件和语气强弱须有原文依据。
4．根据上下文核对公司简称、产品名称、技术路线、金融术语及英文缩读。结合词音、同篇重复提及与官方名称判断，不全局替换多义缩写，不用检索结果改数字或观点，也不擅自扩写简称。先保留原识别候选，再核对官方词形；检索到某个真实作品或公司，只能证明该名称存在，不能单凭题材、人物或业务关联认定录音说的就是它。金额单位、数量级和版本号同样需要直接依据，避免把含混词组补成看似合理的确定数值。
5．遇到影响含义的疑点，先查上下文和专名来源，确有必要时才对少量原音复识别。优先查看同一节目的官方简介及原节目标题，以核对专名；作者事后勘误保留为校对依据，逐字稿仍忠实于音频口述。使用简短术语提示，排除提示回显与重复循环结果。同一模型局部复识别只提供候选，不构成独立听音确认；原识别与复识别冲突时，结合上下文、词音和可靠词形来源判断，仍含混则保留疑点，不凭句子通顺补写。报告实际完成的是文字校订、局部复识别还是逐句听音复核。证据不足时保留原文本，将疑点留在独立记录中。局部裁剪若出现FLAC编码的`invalid block size`，先确认同区间能够解码，再将复核片段输出为PCM WAV；完整原音轨保持不变。
6．对照原稿检查实质内容完整性，重点核对数字、否定、限定、语气及重复表达的作用。严格保留口径核对原有词句完整；轻度整理口径逐处确认删改仅涉及下文允许的内容。长稿分批整理时，为每段保存原始片段的起止下标；汇总后检查连续覆盖、边界衔接及字符差异。下标覆盖通过仍需核对正文，避免范围填全但实质发言漏句。数字和否定字的变化逐项审查，区分专名误识、数值粘连、等义重复清理与真正的语义变化。程序发现数字序列不一致时，逐处核对差异及上下文，确认变动理由及语义保持后再验收；字符差异及删减比例仅辅助定位，不能充当质量目标或替代语义核对。分批边界落在同一轮发言或句中时，合并正文并去除重复角色标签，保持原有信息顺序。
7．最后检查 frontmatter 只有两个字段、来源字符串精确一致、正文没有时间戳，每轮发言仅在开头标一次说话人；成品不添加任何主观评价、解释、推测或校对注释。另行检查会后提示和尾部静音：相互冲突的订阅、打赏、字幕署名等识别结果，应先核对相应音区是否有语音；同模型复识别出现另一套尾句时，不据此挑选更顺口的一套。音频全程解码通过与尾句准确性分别验收，因为解码成功无法排除识别幻觉。

## 轻度整理尺度

### 判断与编辑

1. **按作用判断删留。** 对候选词句，检查删除后是否改变信息、范围、数量、指代、逻辑关系、判断强度或说话者态度。确认这些均未改变，才可删除无实质表达。词表只帮助发现候选项；「其实」「整个」「一个」「相当于」在不同句子中可能承担实际含义，不能全局替换。作用不明时保留。
2. **清理局部口语堆叠。** 删除无意口吃、反复起句、无实质填充，以及同一局部连续重说且没有增量的表达。相邻的中英文同义复述也按含义判断。重复中带有新条件、范围、例子、证据、修正或强调时保留；跨段复述按原顺序保留，不据主题归并。涉及数字、单位或否定的重复清理须单独核对。
3. **只作必要的局部修复。** 清理后修复标点、断句、重复助词和悬空结构；指代清楚时可省去反复出现的主语。保留原有用词和展开顺序，改到自然通顺即可。句子已经通顺就停止，不连续替换为更正式的同义词，不抽象概括多句，也不补全原文未说完的事实或推理。
4. **保留自然口吻与衔接。** 「可以去做」「就是说」「所以说」「你可以理解为」以及开题、解释、转折、收束等表达，按实际作用保留。句间关系依照原话呈现，不为追求简短删去必要连接，也不自行增加因果。仅表示习惯性拖音且无语用作用的语气词可删除；承担询问、推测、态度或实质回应时保留。
5. **保护有意义的限定与修正。** 保留时间、比较对象、范围、可能性、程度、前提、归属和判断强弱。多个词共同表达限定时，须确认剩余表达完整承载原有限定，才可精简。自我修正涉及不同日期、数字、结论或立场时保留修正过程；仅重复起句时保留完整表达。含混处依照校对证据处理，不凭流畅度选定含义。

### 验收与泛化

先逐段对照原稿，确认每个实质判断、论据、例子、条件及修正均有对应内容；再独立通读整理稿，检查残留口语堆叠、断句、衔接与说话口吻。两项都通过即可停止。语义判断由大模型完成，无需为一次性文字整理编写清洗程序。

以下短例用于检查规则在不同语境中的适用边界，不要求其他材料复制其措辞：

- 「我们这个，我们预计大概下个月才能交付。」可整理为「我们预计大概下个月才能交付。」保留预测、估计和时间限定。
- 「整个仓库只有一个出口。」完整保留，「整个」限定范围，「一个」说明数量。
- 「周三发，刚才说错了，是周四发。」保留修正过程，不能仅留下最后日期。
- 「一定要检查，一定要检查，这涉及安全。」保留有意强调的重复。
- 「可以去申请，就是说，先提交材料，再等审核。」保留自然句法及解释、步骤关系。

不设目标删减比例或每句字数。验收依据为实质信息完整、逻辑与语气保真，以及阅读自然；某一主题、产品名或固定表达不形成特殊处理规则。

## 交付说明

按主技能保存到任务所属项目目录，并以 `MEDIA:` 绝对路径交付。音视频转写交付一个完整音频和一个逐字稿 Markdown；继续制作会议纪要时，将校订后的逐字稿完整附入纪要，按当次成品清单交付。验收后删除本次校对记录、备份、原始识别稿、JSON 等过程文件，保留用户原始资料。必要的准确性限制在聊天中简短说明，成品正文保持对应格式。
