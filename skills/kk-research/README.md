# 独立研究模式

`kk-research` 规定如何围绕一个研究问题建立独立上下文：先查本地原文，再由核心分析模型判断资料是否充分；需要补证时，执行侧按权限取得材料。使用者可以核对本轮实际发送的内容。

## 与个人知识库怎样配合

两项 Skill 分别负责资料管理与研究讨论，可以配合使用。

| Skill | 负责什么 | 使用场景 |
|---|---|---|
| [个人知识库](../kk-knowledge-base/SKILL.md) | 保存原文、建立索引、检索和补读，保留来源与阅读范围 | 资料入库、查询已有资料、检查入库结果 |
| [独立研究](SKILL.md) | 管理研究上下文、组织补证、披露模型输入和研究状态 | 围绕明确问题进行连续分析与讨论 |

使用者先通过知识库积累资料。开始独立研究后，取证侧从知识库检索相关原文，将材料及其来源交给核心模型。核心模型判断证据是否充分；有缺口时提出补证要求，再由执行侧按权限检索。

查询知识库可以单独进行。独立研究的完整工作流则需要把本地检索与研究执行器接起来。

## 一次研究怎样进行

1. 使用者明确开启独立研究，给出原始问题，并确认外部取证和私有资料发送范围。
2. 执行侧查询本地资料，必要时补读相邻正文，记录标题、来源、日期与读取范围。
3. 发送前展示本轮材料清单，再将原始问题、必要规则、证据和本项研究的讨论交给核心模型。
4. 核心模型进行分析；需要更多证据时提出具体缺口，执行侧按权限补取材料。
5. 新材料披露后继续讨论。新建研究、恢复与退出分别管理状态，具体行为需由配套执行器实现。

研究模型的可控输入有明确范围。无关聊天、工具定义、认证信息、操作日志与重试记录保留在执行侧；材料中的反向证据、统计口径和原作者限定随原文传入。

## 下载后能获得什么

**当前公开的是两项 Skill 的工作规则与设计文章。完整工作流的运行代码未随包提供。**

| 部分 | 公开内容 | 使用者还需准备 |
|---|---|---|
| 个人知识库 | 入库、原文保存、检索和验收规则 | AnythingLLM Desktop、Ollama嵌入模型、知识库客户端及工作区配置 |
| 独立研究 | 角色分工、输入范围、补证、隐私和请求验收规则 | Hermes clean-research插件、独立模型调用、会话存储、取证客户端及命令路由 |
| 外部补证 | 来源和权限要求 | 所需网页或金融接口的访问能力与授权 |

`/kk-research` 是公开入口名称。下载或加载 `SKILL.md` 后，还需将入口绑定到实际执行器，并核验插件接管、独立请求和状态管理。完整隔离需要检查真实发送内容与回执。

## 安装与验收

将需要的 `kk-research/` 和 `kk-knowledge-base/` 文件夹完整复制到应用的技能目录，再按使用者环境配置依赖、路径、工作区与凭据。仅查看流程规则时，可直接阅读各自的 `SKILL.md`。

部署后分别验证：

- 知识库：解析正文非空、文档关联正确、真实向量接口能召回同一文档原文。
- 独立研究：开启、追问补证、关闭外部取证、退出、恢复和新建研究。
- 输入边界：实际请求只包含允许内容，材料清单与发送载荷一致，并能关联对应回执。

公开文件的格式检查与实际运行分别验收；新环境仍需完成上述功能检查。

## 隐私与资料使用

文件解析、嵌入和存储在本机完成。选中的片段与补读正文会发送给分析模型服务商，使用者需确认资料允许发送的范围。密钥保持本机受控，外部检索仅传递与证据缺口相关的必要信息。
