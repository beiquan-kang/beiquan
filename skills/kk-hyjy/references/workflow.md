# 会议纪要制作流程

以完整校订稿为共同依据，依次提取结构图与结构深读，再附上逐字稿，形成一份 Markdown 报告。文件位置、命名和清理遵循主技能，最终报告模板见 `references/minutes-format.md`。

## 合集与批量任务

1. **先固定清单。** 读取合集完整数据，保存每集的原始顺序、单集标识、标题、链接和标注时长；按单集标识去重，并用程序核对数量与总时长。小宇宙合集可读取页面 `__NEXT_DATA__` 中的 `props.pageProps.collection.target`，再逐集使用现有下载入口；字段结构以实际响应为准。网页可见简介仅用于核对来源。
2. **逐集记录阶段。** 在项目目录保存清单和续跑状态，分别记录下载、转写、校订、纪要验收及汇编状态。续跑先核对同源文件和有效完成记录；文件夹存在或退出码为0都不足以证明纪要完成。现有转写 CLI 持有项目级运行锁，批量调用该入口时顺序执行，避免并发任务争锁。
3. **让后续工作有接续依据。** 长时间转写启用完成通知，保存进程标识及各集结果路径；收到通知后检查实际结果，再继续制作纪要。阶段汇报明确已完成范围，勿把已启动批处理表述为完整任务交付。单集失败须保留待处理状态，最终交付前逐项解决或如实说明缺口。
4. **每集独立验收。** 对每集完整转写执行下文五步，逐集生成含三部分的纪要；不要仅按合集介绍制作摘要，也不要用一份跨集概括替代各集报告。
5. **汇编并核对。** 用户要求 PDF 时加载 `pdf`，按原清单顺序收录各集完整纪要，添加清晰的单集标题与目录或书签。比对清单、已验收纪要和 PDF 中的单集标识，确认无漏集、重复或截断；再检查中文字体、结构图宽度、分页及首尾正文。聊天仅发送用户指定的文件，其余成品留在项目目录；全部验收后再清理过程文件。

## 第一步：获取内容

- 接收 YouTube、小宇宙、哔哩哔哩等媒体链接，或用户提供的 MP3、MP4 等本地文件，核对准确来源与标题。
- 媒体输入先通过 `skill_view(name="kk-hyjy", file_path="references/transcription-workflow.md")` 读取获取与转写流程。检查已有同源成果，复用可验证的完整音轨；需要下载时核对来源、时长与全程解码结果。
- 已有文字稿时用 `read_file` 读取全文，长文件按返回行号继续读取，再进入校订；已有逐字稿须先核对是否符合本次处理口径，通过后可复用。
- 节目页提供官方全文链接时，优先核对并复用全文，按用户要求决定是否获取音频。若提取工具只返回时间戳和说话人，检查浏览器 DOM 的 `textContent` 与正文节点；部分站点的 `innerText` 会漏掉已存在的转录正文。逐段提取说话人和正文，核对段数、首尾及完整覆盖后再整理。
- 网页简介与 Shownote 只用于核对来源和专名。无法取得全文时说明缺失范围及所需输入；仅有节选时先确认用户是否接受按节选制作。

完成条件：取得完整媒体或全文文字稿，来源可追溯，已有材料得到复用。

## 第二步：转录并校订逐字稿

1. 媒体输入按转写参考处理完整音轨，核对进程退出码、完成状态、非空正文、片段覆盖及时间戳范围。
2. 通过 `skill_view(name="kk-hyjy", file_path="references/transcript-format.md")` 读取成品规范。会议纪要附录默认采用其中的轻度整理尺度；用户明确指定其他口径时从其要求。通读全文，校正有依据的识别错误及专名。
3. 完整保留实质内容、原语言、发言顺序、数字、限定、有意义的重复和自我修正。按语境清理无实质口吃、填充与紧邻重复，局部修复句法，保留自然口吻及必要衔接；不补全未完句的含义。按发言轮次标注说话人，内部自然分段，成品删除时间戳。明确要求严格保留时，口头语、重复、结巴及未完句均依该口径保留。
4. 保留用户输入。后续结构图、结构深读和报告附录统一使用这份校订稿；校订稿只需按本次成品清单保存，不额外生成交付副本。

完成条件：全文实质信息、语气和顺序已核对，正文通过本次处理口径的验收，来源与说话人标签明确。以这份定稿作为后续分析及附录一致性比对的依据。

## 第三步：提取全文结构图

### 提取方法

1. **识别主线。** 确定核心主题、主要问题及核心观点。多个独立主题保留并列关系。
2. **梳理关系。** 找出理解主线所必需的概念、论点、证据、步骤和条件，区分包含、并列、支撑、因果、顺序、条件及反馈。箭头方向符合原意，相关性、推测和不确定性保留原有强度。
3. **压缩成图。** 合并重复内容，保留主线和关键分支。论证型内容突出证据与结论，流程型突出步骤与条件，概念型突出分类与联系；多主题内容分别展开，可组合树状结构与关系链。
4. **逐项核对。** 每个节点和每条关系均能在校订稿中找到依据。按需保留关键数字、证据和边界；不同说话人的分歧注明归属，材料缺少的要素直接略去。

### 绘图要求

- 使用中文节点文字和 ASCII 连接线，如 `|`、`+`、`-`、`>`；专名与代码保留标准写法。
- 用 `-->` 表示有方向的关系，必要时标注「支撑」「导致」「依赖」「约束」等名称。树状分支表示层级或并列关系。
- 节点尽量简短；论点节点写成能够独立理解的短句。
- 优先纵向布局，按从上到下、从左到右的顺序组织，控制横向宽度，减少交叉连线。
- 报告中的「全文结构图」部分由标题和一个 `text` 代码块组成。代码块内放完整结构图，根节点写原始标题或主题。

完成条件：核心主题得到覆盖，节点与连线含义准确，图中没有新增事实或未经原文支持的因果关系。

## 第四步：结构深读

通过 `skill_view(name="kk-structural-reading")` 加载结构深读技能，以完整校订稿为输入，按其流程还原正文，并遵循以下纪要约定：

- **展示顺序。** 先给一句话核心答案，再写作者真正回答的问题、一句话发声语境与正文论证地图。存在多方分歧时分别归属，不强行合并立场。
- **正文地图。** 按原文顺序合并语义单元，每个单元保留位置、功能、主张与论证推进。证据、案例、条件和发声者归属均回到完整校订稿核对。
- **位置对应。** 纪要附录删除时间戳，因此默认按话题切成 S1、S2 等单元，在地图中为每个 S 单元注明附录的正文自然段区间 Pn-Pm；P 编号从附录首个正文自然段起连续计算，标题与元信息不计入。编号映射用于回查，不在附录正文插入编号。保留了可核验的原始时间映射时，可以附加时间区间。
- **忠实性。** 保留发声者、时间口径、数字口径、预测及传闻的限定。作者未展开的理由如实说明，不补写事实或推理，不凭常识补全含混数字、单位和专名。
- **篇幅。** 结构深读正文默认约两三千字，材料较薄时缩短并简要说明原因，内容密集时可略超；逐字稿附录不计入此篇幅。
- **交付。** 将完整深读内容纳入纪要的结构深读部分，遵循会议纪要的文件交付约定；独立使用结构深读时遵循其自身规则。

完成条件：核心答案准确，主要语义单元有覆盖，地图可回查附录，所有归属于发声者的判断均有原稿依据。

## 第五步：形成完整报告

1. 通过 `skill_view(name="kk-hyjy", file_path="references/minutes-format.md")` 读取报告模板，沿用原始标题与来源。
2. 将「全文结构图」「结构深读」「逐字稿」依次放入同一文档。附录完整保留第二步的校订稿正文，发言顺序不变。
3. 按模板验收结构、内容及附录一致性，使用 `write_file` 保存到任务所属项目目录，并确认文件非空。音频按转写参考验证。
4. 验收后清理本次过程文件。最终回复简短说明结果，给出报告的绝对路径并通过 `MEDIA:` 交付；从音视频开始处理时同时交付完整音频。

完成条件：报告符合三部分结构，通过内容与格式检查，所交付地址对应已保存的成品。

## 合集与PDF汇编

- 用户要求处理合集全部节目时，先解析完整清单，保存单集标识、精确标题、来源及总数；逐集跟踪转写、校订和验收，最后用工具核对成品数等于清单数。
- 分批转写完成后即可逐集整理，与其余音频的转写并行；后台完成通知必须继续触发下一阶段，不能停在转写完成。维持可恢复的项目状态，避免重复下载。
- 用户指定只交付PDF时，音频和Markdown保留本地，聊天仅交付最终PDF。按合集顺序汇编每集三部分，添加目录、章节书签与简短准确性说明。
- 中文PDF导出前检查实际字体的字符覆盖，特别是论证链中的箭头等符号。缺字使用包含该字符的嵌入字体，保持原文符号。
- 验证PDF时移除提取文本中的页眉页码，再逐项比对全部结构深读单元和逐字稿段落，防止跨页段落被误判漏失；同时抽查渲染页面，确认无裁切、乱码与重叠。
- 校订中仅凭上下文逻辑不得添加或删除否定。复识别候选冲突时保留疑点，分析部分仅采用明确证据。
