# 平台音轨获取与验收

本文件用于在线媒体的前置检查、下载诊断和平台能力确认。正式程序位置见 `references/transcription-workflow.md`；脚本与依赖路径相对于运行项目，任务成品及过程文件保存在任务所属项目目录。

## 1．先核对目标与已有证据

1. 取得用户给定的准确链接，保留视频标识、分P和单集编号。只处理获授权的单项媒体。
2. 优先检查任务目录及用户给定位置中的同源音频及 Markdown，用 `source` 核对来源。续跑时读取尚未清理的临时验证记录；用户提到其他对话时，使用 `session_search` 查证已报告结果。过程记录已删除时，直接复验现存成品，不重建冗余档案。
3. 分开确认平台访问、完整下载、解码和转写。`doctor` 报告的工具或模型存在，只能证明对应检查项通过。
4. 按下表选择已有入口，先做匿名访问实测；只有目标平台的返回信息明确要求登录时，才进入凭据授权流程。

| 平台 | 获取顺序 | 关键校验 |
|---|---|---|
| YouTube | 检查 yt-dlp、匹配的 EJS 和已启用的 JavaScript 运行环境，再提取单视频音轨 | 根据实际返回判断是否需要登录；核对视频标识、完整时长、HTTP 音轨格式 |
| B站标准 `/video/BV…` | 访问首页建立匿名访客会话，再请求 `/x/web-interface/view` 和 `/x/player/playurl` | 核对 BV、分P、播放权限及各阶段时长；拒绝付费、试听、DRM、交互及跳转内容 |
| 小宇宙单集 | 解析页面 `__NEXT_DATA__` 中的单集元数据与 `media.source.url`，下载完整音轨 | 核对单集标识、标注时长、下载实测时长和全程解码结果 |
| X／Twitter | 用项目内 yt-dlp 匿名提取准确帖子链接，查询格式与字幕，再下载指定媒体 | 帖子ID与所附视频ID可能不同；保留原链接，核对视频时长、字幕覆盖与实际音轨 |

### X 视频与字幕

- 通过 `terminal` 调用项目解释器的 `-m yt_dlp --ignore-config --no-plugin-dirs --skip-download --list-subs <准确链接>`，检查现有字幕；使用 `--write-subs --sub-langs <实际语言> --sub-format vtt` 获取。平台自动字幕仅作为识别稿，仍须校订；能取得全片字幕时可复用，避免重复语音识别。
- X 的VTT可能用 `<X-word-ms ...>` 包裹每条文本。解析时保留时间与顺序，移除标签并解码HTML实体，核对首尾时间是否覆盖实际媒体，避免只提取普通裸文本而遗漏正文。
- 用户要求保存视频时，选择包含视频与声音的格式；直接HTTP格式可能明显大于同分辨率HLS，先用 `--list-formats` 核对。下载成功后可用FFmpeg的 `-map 0:a:0 -vn -c:a copy` 无损抽取M4A，并验证完整音轨。
- `--print before_dl:...` 或 `after_move:...` 可能使进度输出安静。判断下载是否运行应结合进程状态与文件大小；不要据日志暂时无增长重复启动下载。
- 用户要求中文纪要时，分析正文写中文，完整发言另作中文译稿附入，明确采用平台字幕校订与翻译，保留不确定措辞；跨段翻译检查句子边界和连续发言标签。

B站其他链接形态按现有 yt-dlp 路径逐条验证。先区分网页访问与播放接口的结果，因为网页 HTTP 拒绝状态无法证明播放接口也受阻。小宇宙的单集地址解析成功后仍须下载和解码，才能报告完整音轨可用。

## 2．检查 YouTube 提取组件

1. 读取项目 `scripts/media.py` 的实际调用参数和 `.venv` 中的包元数据。避免仅凭机器上存在 Node 就宣布可用，因为 yt-dlp 还需要显式启用它。
2. 按 yt-dlp 官方 EJS 文档核对运行环境支持。通过项目解释器运行下列只读命令，取得当前安装版要求的 EJS 版本：

```bash
.venv/Scripts/python.exe -c 'import importlib.metadata as m; print("\n".join(r for r in m.requires("yt-dlp") or [] if "ejs" in r.lower()))'
```

3. 缺少 EJS 时，将匹配版本安装到项目 `.venv`；安装器缓存和临时目录也放在项目内。通过 `<项目解释器> -m pip install --no-deps <匹配的包版本>` 安装，并更新项目依赖文件。不要同时升级语音识别依赖。
4. 提取调用先用 `--no-js-runtimes` 清空默认运行环境，再以 `--js-runtimes node:<实际路径>` 显式启用 Node。将此设置限定于 YouTube 域名，保留 `--no-remote-components`、外部配置禁用和插件禁用；EJS 从项目已安装包加载。
5. 用回归测试验证实际参数，再用授权链接验收。n challenge 失败提示需要检查组件与运行参数；登录要求须另行核对。

官方说明：https://github.com/yt-dlp/yt-dlp/wiki/EJS 。

## 3．定位失败阶段

| 观察到的结果 | 下一步 | 结论范围 |
|---|---|---|
| 入口只返回泛化的提取失败 | 按 `scripts/media.py` 原参数单独执行元数据提取，捕获并脱敏 stderr | 先取得底层证据，再解释原因 |
| `LOGIN_REQUIRED` 或要求确认真人 | 说明验证要求，按凭据规则让用户完成登录与授权 | 该链接、当前会话与网络的验证要求 |
| 单个 HTTP 拒绝状态 | 分别检查网页、接口、请求头、匿名会话和既有代理 | 暂不能判定必须登录或账号受罚 |
| 取得媒体地址后连接超时 | 对同一地址做小范围字节请求，比较直连和用户已有代理 | 区分提取成功与媒体连接失败 |
| 整文件请求缓慢，范围请求正常 | 使用经过连续性校验的顺序 Range 下载 | 确认最终完整文件后才能交付 |
| Cookie 加入后错误变成 n challenge 或无音轨 | 检查 EJS 和运行参数，再验收可播放音轨 | 错误变化仅说明请求到达了不同阶段 |

诊断只输出状态、错误类型、时长和字节数；在日志落盘前隐藏 Cookie、签名地址、代理凭据和认证头。不要为调试复制完整提取 JSON，因为其中可能包含可用的媒体签名或登录信息。

## 4．保持媒体请求的网络路径一致

- 使用用户已有的环境或 Windows 系统代理，因为提取器与实际媒体下载走不同出口时可能失败。
- 保持 `session.trust_env=False`，同时在每次请求显式传入 `requests.utils.get_environ_proxies(url)`，以使用已有代理并避免 `.netrc` 自动注入凭据。
- 每次重定向重新校验地址并计算代理设置。仅传递项目允许的请求头，Cookie 保留原域名与路径约束。
- 对 Googlevideo 完整 HTTP 音轨采用顺序 Range 请求，每次至多4 MiB，写入同一个媒体文件。逐段校验206状态、`Content-Range` 连续性、总大小稳定、响应长度和总耗时；失败时清理部分下载。
- Range 只改变传输方式。必须在完整文件就绪后整体转换为 FLAC，随后按完整音轨判断云端准入。

## 5．验收并汇总能力

1. 校验下载字节数、节目元数据时长、媒体实测时长和音轨存在性。
2. 下载验收使用 FFmpeg 全程解码，并检查退出码和 stderr；只探测文件头无法证明整段媒体完整。
3. 核对来源、访问方式、是否使用账号 Cookie、下载状态、字节数、时长、解码结果及是否执行转写；必要记录仅在临时任务目录使用，验收后清理，必要结论在聊天中报告。测试替身只证明代码行为，真实媒体实测才能证明该链接可用。
4. 跨平台总结采用「平台｜完整音轨下载｜解码或转写状态｜本次登录条件」。只列用户关心的平台，将结论限定在已验收样例。
5. 某次使用登录 Cookie 成功，只能证明该路径成功；若匿名路径曾返回登录要求，可说明本次环境需要登录。不要推广为该平台所有内容永久需要登录。
