# YouTube 登录凭据的授权与使用

本文件用于平台明确要求登录、用户询问封号风险或提供 Cookie 的情况。登录操作由用户在自己的浏览器完成；账号凭据只在本地处理。

## 1．先解释操作范围与风险

- 分别说明在 YouTube 官网正常登录观看，以及将登录 Cookie 用于 yt-dlp 自动下载；两种操作的授权范围和风险依据不同。
- 将 yt-dlp 的临时或永久封禁警告归于维护者，并核对官方说明。缺少发生率数据时，不编造百分比，不把单次或少量下载定为低风险。
- 请求速率说明不能充当安全额度；真人验证提示也不足以判断账号已经受罚。账号承担重要业务时，向用户说明潜在损失，由其决定是否授权。
- 浏览器登录后，脚本仍须取得获授权的有效 Cookie；浏览器会话不会自动成为脚本的输入。

官方说明：https://github.com/yt-dlp/yt-dlp/wiki/Extractors 。

## 2．选择获得凭据的方式

### 用户明确要求直接读取浏览器

1. 仅检查用户指定的浏览器和目标站点，不枚举其他站点的 Cookie 值。
2. 先尝试正常权限下的读取方式，只返回可读性、格式、域名范围和数量。
3. 遇到文件权限或浏览器加密限制时，报告实际阻塞，并转为用户在浏览器内导出。不要擅自关闭浏览器、提升权限或降低浏览器安全设置。

### 用户手动导出

1. 让用户在 Edge 中审阅并安装 yt-dlp FAQ 推荐的 **Get cookies.txt LOCALLY**。官方商店地址：https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc 。
2. 在已登录的 YouTube 页面打开扩展，选择 Netscape 格式，导出范围限定为当前 `youtube.com`。
3. 建议存放于项目 `.state/youtube-cookies.txt`。使用前检查该目录受到项目版本控制忽略规则保护；不要将凭据放入成品或验收资料。
4. 让用户用普通文本发送本地路径和使用授权。明确说明不要使用 `@file`、附件上传或粘贴内容，因为桌面可能将文件正文展开进聊天。
5. 如需长期复用，按 yt-dlp 官方流程从专用私密浏览会话导出：登录后在同一标签访问 `https://www.youtube.com/robots.txt`，仅导出 YouTube 域的 Cookie，然后关闭该私密窗口。需重新登录时由用户完成，不承诺 Cookie 永久有效。

不要直接采用全浏览器 Cookie 导出命令，因为即使同时传入视频 URL，工具也可能导出其他站点的凭据。

## 3．验证本地文件并执行

1. 使用本地 Python 的 `http.cookiejar.MozillaCookieJar` 解析文件；不要用 `read_file` 输出 Cookie 正文。
2. 只返回文件是否存在、Netscape 格式是否有效、域名集合、总条目数和未过期条目数。域名应仅为 `youtube.com` 或其子域；出现其他站点时先停止使用并说明范围问题。
3. 用项目入口传入 `--cookies-file <获授权文件路径>`。动态路径与 URL 使用 `subprocess.run()` 参数列表或 `shlex.quote()`，不将 Cookie 值放入命令行。
4. 提取器使用项目内临时副本，结束后清理副本，并保留用户原文件。诊断只在临时任务目录保存脱敏后的错误，验收后删除；退出码与最终媒体结果决定是否成功。
5. Cookie 失效时，请用户更新本地导出文件，不自动扩展到其他浏览器、账号或站点。

官方格式说明：https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp 。

## 4．处理意外展开到聊天的凭据

- 不复述、引用或复制已展开的 Cookie，也不把它写进报告、技能或脚本。
- 提醒用户撤销对应 Google 登录会话，并删除已导出的旧文件。删除本地文件本身无法撤销仍有效的会话。
- 后续只接收普通文本路径和授权；需要重新导出时使用新的有效会话。
